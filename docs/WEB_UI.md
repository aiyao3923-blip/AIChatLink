# AIChatLink Web UI — 视觉系统（纸与墨）

本文档是 `/`（房间）与 `/setup`（名册）共用视觉系统的唯一依据。
它约束**呈现层**：不改协议、存储、路由语义或 unrestricted 合同。

重建原因见「一、为什么重做」。实现细节见 `web/tokens.css`、`web/styles.css`、`web/setup.css`。

---

## 一、为什么重做（问题不是「缺装饰」，是「缺秩序」）

旧样式不是设计产物，是 18 版 `styles.css` 的堆积：从 `52c55cb`「Feishu-style light theme」起家（企业 IM 密度），
之后每加一个 driver 就加一个色调、每加一个面板就加一层边框。

| 证据 | 旧值 | 结果 |
| --- | --- | --- |
| 字号 | 75 处声明 / 27 种字号，24 种 ≤ 0.72rem | 没有字阶，层级被压平，11px 主体在大屏上变成噪点 |
| 颜色 | 95 个 hex + 72 个 token，8 个 Agent 色 × 3 处使用 | 唯一品牌色被 24 处彩色信号稀释 |
| 对比度 | `#8a94a8` on `#f5f7fa` = 2.84:1，placeholder 2.51:1 | 次级文字低于 WCAG 3:1，观感「脏」 |
| 版式 | 对话列无 `max-width`；侧栏 318px | 1600px 下正文行长 120+ 字符；低频操作占据 20% 宽度 |
| 重复 | 7 张 Agent 卡各带路径、能力、常驻「重启」 | 视觉噪音与可读性直接冲突 |

**四条设计律**（本次重做的判据）：

1. 一个强调色；Agent 身份色只允许出现在头像底、名字、目标芯片圆点。
2. 字号封顶 7 级；中文不小于 11px；正文 15px/1.8。
3. 表面封顶 3 层（canvas / paper / well）；分隔优先用留白，其次用发丝线。
4. 阅读列 780px 居中；低频控件降级或折叠，不常驻正文区。

## 二、横纵分析（学习依据）

### 横向：同类产品的事实

| 产品 | 布局事实 | 配色事实 | 迁移到 AIChatLink 的结论 |
| --- | --- | --- | --- |
| ChatGPT | 消息列 ≈768px（48rem）居中，画布铺满不装箱；16px/1.5 | `#fff`/`#f9f9f9`、发丝线 `#ededed`，单一强调色 | 骨架早已同质化，差异化在排版 |
| Claude | 同样三段式，留白更奢侈，标题衬线 | 暖纸 `#faf9f5`、陶土 `#d97757`，中性色全部偏暖 | 温度即品牌，不是 hue 数量 |
| Linear (2024) | 中性色「去蓝」，chrome 降噪，内容对比拉高 | 98 个手调变量 → base/accent/contrast 三个输入在 LCH 生成 | 减法 + 语义化生成 |
| Vercel Geist | 每色 10 阶，语义绑台阶（100 底 / 400 边 / 900 文本） | 灰阶承担 90% 表面 | token 必须按语义绑台阶 |
| Slack | 侧栏 260px、消息 15/22、时间戳 12px `#616061`、头像 36×36 | 身份靠头像 + 名字，不靠染色 | 多人房间的身份编码必须低面积 |
| Discord | 角色色染用户名 | 长期可读性投诉 | 把 Agent 色刷到文字/边框上是已知翻车路径 |
| Lobe UI | 侧栏 280px、header 64px、对话最小宽 850 | 三层表面 | 表面层级 ≤ 3 足够 |

### 纵向：演化脉络

- **2022** ChatGPT：去气泡灰底对话流 → 确立「画布 + 居中列」。
- **2023** 开源聊天框架：把「侧栏 + 会话列表 + 气泡 + 后台组件库味」固化成模板（旧 AIChatLink 继承的是这一段）。
- **2024.03** Linear 重设计：3 输入 + LCH 生成主题、去蓝中性、降 chrome → 让内容说话成为高端线共识。
- **2024** Claude 换装：暖纸 + 陶土 + 衬线 → 温度即品牌。
- **2025–2026** 全行业骨架收敛，差异只剩排版、色彩温度、动效质感。

结论：AIChatLink 的结构性问题不是「不够花」，而是**照抄了企业后台的密度，却承担的是阅读型界面**。
因此本次选择「纸与墨」：暖中性画布 + 衬线标题 + 一个陶土强调色 + 780px 阅读列。

## 三、Token（`web/tokens.css`）

| 语义 | Light | Dark |
| --- | --- | --- |
| `--canvas` 画布 | `#faf9f5` | `#12110e` |
| `--paper` 卡片 | `#ffffff` | `#1a1815` |
| `--paper-2` 悬停/表头 | `#f4f1e8` | `#221f1a` |
| `--well` 气泡/代码/引用 | `#f2eee4` | `#24211b` |
| `--ink` / `--ink-2` | `#191711` / `#37332a` | `#f4f1e6` / `#dad5c7` |
| `--muted` / `--faint` | `#6e6a5f` / `#8b8678` | `#a29c8e` / `#7c766a` |
| `--line` / `--line-2` / `--line-3` | `#e6e2d6` / `#d5cfbe` / `#b8b0a0` | `#2b2822` / `#3a362e` / `#4c4739` |
| `--accent` | `#a8481f` | `#e0824f` |

约束：

- `--faint` 只用于装饰与图标描边，**不用于可读文字**；所有正文/元数据 ≥ 4.5:1。
- 主按钮用 `--ink`（纸的反色），不用品牌色铺面；`--accent` 只出现在焦点环、流式光标、选中态、链接。
- 主按钮 hover 才切到 `--accent-deep`。这是「纸与墨」的手法：颜色是标点，不是背景。

### 字阶（7 级，rem）

| Token | px | 用途 |
| --- | --- | --- |
| `--fs-10` | 10 | 拉丁小标（mono / uppercase / `.14em`），数字与徽标 |
| `--fs-11` | 11 | 元数据、芯片、按钮副标签（中文下限） |
| `--fs-12` | 12 | 控件、列表、系统提示 |
| `--fs-13` | 13 | 发送者名、表单标签、抽屉正文 |
| `--fs-15` | 15 | 消息正文（`--lh-body` 1.8） |
| `--fs-20` | 20 | 区域标题 |
| `--fs-26` / `--fs-34` | 26 / 34 | 空态与 setup 主标题（衬线） |

字体：`--font-sans` = Noto Sans SC → 系统无衬线；`--font-serif` = Noto Serif SC → 系统衬线。
**不加载网络字体**（CSP `default-src 'self'`），因此正文与标题均为系统字体，无 FOUT。

几何：`--r-xs 6 / --r-sm 8 / --r-md 12 / --r-lg 16 / --r-pill / --r-avatar 10`；间距 4/8/12/16/24/32/48。
唯一例外是用户气泡的 `14 14 4 14`（右下角收口指向发送者）。

## 五、身份色（Agent tone）

机制不变：`actorToneClass()` 按 actor id 前缀选内置色，自定义 id 按哈希取 `actor-dynamic-0..5`（D-017）。

变化在**用法**：色调只注入 `--tone` 变量，然后仅四处消费——

1. 头像底色 `color-mix(--tone 11%, transparent)` 与同色字；
2. 发送者名 `color: --tone`；
3. 目标芯片选中态（8% 底 + 30% 边 + 圆点）；
4. 无边框、无圆点、无卡片描边、无气泡背景色。

这样 7 个 Agent 同时在线时，屏幕上只有 7 个约 30px² 的色块和 7 个名字，而不是 24 处彩色信号。

## 六、富文本块级渲染（`web/rich-text.ts`）

对话区是阅读主体，模型输出必须按它自己写的结构呈现，不得拍平成一段。语法是一份**封闭白名单**，未识别的标记保持字面文本：

| 块 | 语法 | DOM |
| --- | --- | --- |
| 段落 | 空行分隔（段内单换行保留） | `p.rt-p` |
| 标题 | `#`…`######` | `h3..h6.rt-h[data-level]` |
| 无序 / 有序列表 | `- `/`* `/`+ ` / `1. `，缩进嵌套 | `ul.rt-list` / `ol.rt-list` + `li.rt-li` |
| 引用 | `> ` | `blockquote.rt-quote` |
| 分隔线 | `---` / `***` / `___` | `hr.rt-hr` |
| 围栏代码 | ```` ```lang ```` | `.code-block`（带语言与复制） |
| 表格 | `\| a \| b \|` + `\| --- \|` | `.rt-table-wrap > table.rt-table` |
| 行内 | `**粗**` `__粗__` `*斜*` `_斜_` `~~删~~` `` `码` `` `[字](url)` 裸 URL | `strong/em/del/inline-code/inline-link` |

规则：

1. **换行归属**：`white-space: pre-wrap` 只给 `p.rt-p` / `li.rt-li` / 表格单元，块级标记自己负责缩进；禁止再对 `.event-content` 整体开 `pre-wrap`（会把列表缩进和段落间距一起吃掉）。
2. **宽松降级**：未闭合围栏、未配对 `**`、跨行的强调、非 http(s) URL 一律当字面文本，绝不吞字符、绝不补全。
3. **CSP 不变**：只用 `createElement` / `textContent`，不拼 HTML 字符串。
4. **推理流同语法**：`turn.reasoning.recorded` 用同一套块级渲染，展开态限高 24em 内部滚动——推理是证据，不是正文，不得顶掉整页。
5. **`.event-content` 必须是 `div`**：它现在装的是块级节点，不能是 `<p>`。
6. **助理抽屉同语法**：房间助理的气泡（`.assistant-bubble`）内部同样走 `renderRichContent`，字号取 `.assistant-timeline .event-content`（13px）。

## 七、禁止清单（新增样式前先读）

- 不新增字号：需要更小/更大时先改字阶表，并在本文件登记用途。
- 不新增几何字面 px：≥4px 的尺寸一律写 `calc(N * var(--px))`（见§十四）；只有 1px 发丝线、
  `--shadow-*` 与断点条件允许保留字面 px。
- 不在 `html` 用裸 `vw` 定字号（WCAG F94）；根字号必须保留 `rem` 基准。
- 不新增 hex：一律取 token；确需新语义（例如 `--bubble-note`）先在 `tokens.css` 定义明暗两值。
- 不用 Status 色（ok/warn/danger）做装饰；它们只表达状态。
- 不给卡片加边框 + 阴影 + 圆角三件套；三选二。
- 不把「重启 / 压缩 / 设置」这类低频动作常驻正文区；放进侧栏展开态或抽屉。
- 侧栏不做「多选高亮」：强调边框只有一行，就是主时间线正在显示的那段；`当前 / 进行中` 只是文案，不能拿来当选中态。
- 系统/状态行不超过一行：Turn 状态、记忆写入、工具记录都压成 11px 单行，不写第二段解释。
- 不设常驻操作提示行（`Enter 发送 · Shift+Enter 换行`）：占一整行却不改变任何决定，提示进占位符，状态槽只留错误与进行中反馈。
- 侧栏不重复「已就绪」；只有异常状态（重试 / 失败 / 待重启 / 已停用）才出现文字。
- 设置页不提供分步向导、整机 CLI 探测清单、运行合同说明块；driver 可用性只作为 Driver 字段旁的一个词（已找到 / 未找到）。
- 设置页不把 N 个 Agent 纵向平铺：一律「名册轨道 + 单卡详情」，全局项（端口 / 存储）收进折叠区。
- 设置项必须真的生效：driver 不转发的能力要禁用而不是静默保存。
  | driver | 模型 | 思考强度 |
  | --- | --- | --- |
  | Codex App Server | `-c model=` | 8 档（none…ultra） |
  | Claude Code | `--model` | 5 档（low…max） |
  | Grok / Kimi / Hermes ACP | 不支持（禁用） | 不支持（禁用） |
- 轨道上显示的值必须与详情一致：名称、ID、模型、启用状态任一变化都要重绘轨道。
- 不显示「已载入当前名册」这类无决策的提示条；只有真实的配置错误才占顶部横幅。
- 不引入新依赖（图标库、CSS 框架、网络字体）。图标用内联 SVG 或单一字形。
- 活动栏不做第二名册：不放名字、driver、状态文字、重启/配置；只有头像、工作环、完成点。
- 忙碌锁不是审批层：忙碌时草稿、目标选择、单 Turn 取消都可用，忙碌键只表达「终止本轮」，不得用
  `NATIVE_POLICY_BLOCKED` 或 pending request 表达；终止不弹确认框、不自动补发 prompt。
- **草稿属于视图，不属于标签页**：key = `aichatlink:draft:<ws|primary>:<conv|live>`（`web/draft-scope.ts`）。
  切对话先存旧视图、再恢复新视图，所以「切走前输入框里是什么，切回来还是什么」；换房间整页 reload 也按 URL 取值，
  新房间的输入框**不会**继承上一个房间的草稿。
- 完成点不持久化：不写 localStorage/DB，不跨刷新；它回答「这一轮谁先完成」，不是未读系统。
- 不在 `prefers-reduced-motion` 下删除「在工作」信号：`tokens.css` 的全局动画重置会豁免
  工作环与发送/终止环（降速到 `--dur-busy` 2400ms），其余过渡与装饰仍按 reduce 关闭（D-049）。
- 活动栏与忙碌锁只能由 `trackTurnEnvelope()` 投影：`renderTurn()` 的同步是幂等补充，
  不能成为唯一路径——窗格镜头会拒收不属于自己 Agent 的 Turn。

## 九、滚动跟随（对话区与助理抽屉）

- **默认跟随**：新消息、正文增量、推理增量、工具进度都重新贴底；卡片长高也算（MutationObserver 合并到一帧），不是只在新气泡追加时跟。
- **跟随用瞬时滚动**：`scrollTop` 直接赋值并临时关掉 `scroll-behavior: smooth`，否则每个增量都会启动一次动画、越跑越落后。
- **阅读优先**：在对话区内滚轮 / 触摸 / 指针按下 / 翻页键任一次操作即暂停跟随，**不会自动恢复**；只有点回到最新箭头、或自己发出一条消息才恢复。多窗格下**不再有「滚回底部自动恢复」**：延迟的程序化 scroll 事件会在暂停后误恢复（见 §13.6）。
- **回到最新**：只要离底部超过 120px 就出现，不依赖是否有新气泡；出现时若期间追加了 N 条新气泡，角标写 N（>99 写 `99+`）。

## 十、富文本回归纪律

模型输出的排版不是装饰，是信息。下列任一情况视同回归：

- 一条含空行的回答被渲染成单一段落（`\n\n` 丢失）；
- 列表项的 `- ` / `1. ` 标记以字面文本出现，或列表与正文挤在同一行；
- `**...**` 原样显示；
- 代码围栏没有黑底样式或丢失复制按钮；
- 推理记录展开后没有任何高度限制，把整页顶掉；
- 房间助理气泡失去内边距/底色，或助理回答被压成一段。

## 十一、对话目录（消息索引）与旧对话续聊

### 11.1 对话目录

**用途**：在长对话里只回看「我说过什么」，并一键跳回原位置。它不是第二种 transcript，也不是全文搜索。

| 项 | 规则 |
| --- | --- |
| 入口 | `对话目录` 浮动按钮（与 `回到最新` 同形：34px 圆、`--paper` 底、`--line-2` 边、列表字形），固定在上、箭头固定在下；只有当前视图里存在用户消息时出现 |
| 面板 | `--paper` 卡、`--r-md`、`--shadow-3`，宽 `min(360px, 100vw - 48px)`，高 `min(420px, 58vh)` 内部滚动；从右下方贴着按钮向上展开，覆盖正文但不推动布局 |
| 头部 | eyebrow `My messages`（`--fs-10` mono）+ 衬线 `对话目录`（`--fs-16`）+ 右上 `×`；点 `×` 或换对话即关闭 |
| 条目 | 一条用户消息一行：`--well` 底、`--fs-10` mono 序号（1 起）+ 两行截断（`-webkit-line-clamp: 2`）正文；hover 变 `--paper-2` |
| 内容范围 | 只收 `actor.kind=user` 的 `message.created`，按发送顺序编号；Agent 回复、系统事件、`operator.dispatch` 一律不进；历史回放（续聊种子 + 旧对话）同样只收用户消息 |
| 跳转 | 点条目关闭面板并 `scrollIntoView({block:"center"})`，目标卡片加 1.4s 高亮；跳转即暂停自动贴底 |
| 可达性 | **每个序号必须能跳到真实节点**：已被「收起较早消息」折叠掉的气泡不进目录，宁可少一条也不给死链；重新打开面板时按当前 DOM 重算 |

### 11.2 旧对话续聊

D-034 曾把历史对话定为纯只读。现在的语义是：**点开是只读回放，第一条新消息才把它续成新纪元**。

1. 点侧栏已关闭对话 → 主时间线回放它的全部可见区间（`resumedFrom` 种子 + 自身），顶部出现 `正在查看「标题」… 发送新消息会以这段对话为上下文，开一段新的继续对话` 与 `回到当前对话`；此时不写任何数据。侧栏的强调边框同步移到这一段（`is-viewing`），`当前` 纪元降为弱边；`?conv=<id>` 同时写入 URL，刷新后仍在同一段回放上。
2. 在回放态发送 → 先 `POST /api/conversations/resume`（写一条带续聊种子的 `context.reset`），再 `POST /api/messages` 发进新纪元；输入器状态依次显示 `正在以这段对话为上下文继续…` → `已提交`。
3. 新纪元在侧栏显示为 `当前`，副标题 `续自 <源对话>`；源对话回到普通历史项。时间线里保留回放内容，并用两条发丝边界区分：
   - `以上为「标题」的历史记录`
   - `继续自「标题」· 下面是这次的新消息`
4. 回放态不锁输入器（与纯只读抽屉不同）：输入即续聊，这是本功能的入口；`回到当前对话` 才是放弃回放。
5. 目录、贴底跟随、发送器计数都按当前视图计算，不跨纪元混算。
6. **切换不整页重载**：进入回放先取完全部区间再清空重绘；`回到当前对话` 在同一页内重建活纪元
   （`rebuildLiveEpoch()`），EventSource 与 seq 游标持续，重绘期间到达的 live 帧排队后按序补放。
   清空与绘制之间不允许出现 `await`——那段空窗就是用户看到的频闪。跨工作目录才整页重载（§12.1）。

**禁止**：点击侧栏就静默 reset（会产生一堆空纪元）；把续聊做成复制一份 transcript（种子只是区间引用）；用蓝色/彩色圆形按钮（见 §三 一个强调色与 §七 禁止清单）。

## 十二、多工作目录壳层（D-040）

### 12.1 状态与切换

- **唯一事实源 = URL**：`?ws=<workspaceId>`；缺省即主目录。切换 = `location.assign` 整页重载，EventSource / seq 游标 / 回放视图 / 在飞提交一次性归零。
- **跨目录点会话**：`?ws=<目标>&conv=<conversationId>`；首屏拿到该目录的 conversations 后，用既有 `enterConversationView()` 打开。绝不跨目录复用 seq range。
- **`?conv=` 跟着回放走**：进入回放 `replaceState` 写入，退出回放 / 续聊成新纪元 / 新建对话前删除。只写不删会让刷新或跨目录重载按 URL 把刚离开的历史视图重新打开（见 D-042、D-058）。
- **左栏分组**：`GET /api/workspaces` 拿到主目录 + 已添加目录；每个目录再拉 `/api/conversations?ws=`。主目录在前，其余按注册顺序；失败组必须显示错误而不是空白。
- **删除会话**：侧栏图标 + 确认 = `POST /api/conversations/delete` 的服务端永久清除（D-043）；没有本地隐藏集合，也没有「显示已隐藏」。删除活动对话后服务端先 reset 再清除，主时间线随 `context.reset` 落到新的空纪元；删除已关闭对话只刷新列表。

### 12.2 工作目录选择器

| 区域 | 规则 |
| --- | --- |
| 入口 | 输入器 `＋ 工作目录 …` 按钮（`#composer-workspace`），不再链到 `/setup` |
| 已添加 | 列表行 = 标签 + 完整路径 + 状态徽标（主目录 / N 个 Agent / 启动中 / 启动失败 / 未启动）；点行切换；hover 出现 `×` 移除（主目录不可移除） |
| 浏览 | 复用 `GET /api/setup/workspace`：快捷入口、`↑` 上级、子目录（含 `.git` 标记）、`使用此目录`；不读文件内容 |
| 新增 | `POST /api/workspaces`（`x-aichatlink-setup: 1`）→ 轮询 `/api/workspaces`（1.5s）直到 `ready` 或 `failed` → 跳转；失败把错误留在对话框状态行 |
| 移除 | `DELETE /api/workspaces/:id`；当前目录被移除则跳回主目录；数据目录保留 |

### 12.3 顶栏名册

- 名册属于**当前 workspace**：`/api/bootstrap?ws=` 决定；切换目录后随整页重载更换。
- 每个 Agent 一项，`--tone` 只染头像底与名字；状态点颜色：ready=ok、starting/restarting=warn、failed/disabled=faint。
- 动作图标：`⟳` 调 `POST /api/agents/:id/restart?ws=`；`⚙` 进 `/setup`。都只用 `aria-label`/`title` 表达，不写文字。
- `/setup` 已停用的 Agent 保留但降透明度；`pending_restart` 的 Agent 状态点仍显示失败色。

### 12.4 分组折叠与目录内新建对话

- **折叠**：组头最左的箭头只收起该组的会话列表；分组头、会话数、失败说明始终可见（折叠不是删除，也不是关闭 runtime）。状态按 `workspaceId` 持久化到 `localStorage` 的 `aichatlink:collapsed-workspaces`，默认展开；切到该目录、在该目录新建对话时自动展开。
- **目录内新建**：组头 `＋` 直接 `POST /api/context/reset?ws=<id>`（旧纪元保留为历史），成功后再跳到该目录的 `?ws=`；不先切目录再新建，也不复制 transcript。`＋` 只在 `status=ready` 时可点。
- **新对话会终止本房间的工作**：面板标题的 `＋ 对话`（以及组头 `＋`）会替换全部 native session，所以确认框必须写出**正在运行的任务数**（`当前有 N 个任务正在运行，继续会终止它们，未完成的回复会丢失`）；跨目录新建时改为写明「该工作目录下正在运行的任务会被终止」。只写「上下文会重置」会让用户以为任务还在跑。
- **新房间不走 reset**：`＋ 房间` 只打开工作目录选择器（`POST /api/workspaces` → `navigateToWorkspace`），另一个房间有自己的 DB/room/Agent 进程，因此「一边跑一边开另一个」不需要任何额外机制；副作用是每个房间各起一套 Agent 进程，房间数线性放大。
- **组头 `⋯`**：`position: fixed` 弹层（避开会话栏的滚动裁剪），条目 = 打开文件夹（`/api/setup/workspace/reveal`）/ 重启 Agent 会话 / 移除工作目录；后两项只对已添加目录出现。点击外部、`Esc`、滚动或缩放即关闭。

### 12.5 禁止

- 不在左栏恢复 Agent 卡片、公共记忆、本地说明或「添加 Agent」入口。
- 不把 workspace 列表塞进 `aichatlink.json`，也不把「当前目录」只存在 localStorage。
- 不在切换目录时复用旧的 EventSource / seq / 回放视图；不要让 `?ws=` 请求落回主 runtime。

## 十三、多窗格（pane grid，D-045）

**用途**：同时看多个 Agent 的输出。一页仍是**一个 workspace、一个活纪元、一条 EventSource、一份 `state`**；
窗格是这份状态的只读投影（镜片），不是第二个 App 实例、不是第二条 SSE、不是第二个输入器。

### 13.1 布局

- `#pane-grid` 是六轨 CSS Grid（`repeat(6, minmax(0,1fr))`），`gap:1px`、底色 `--line`、每格 `--canvas`；
  列/跨列由 `paneSpans()`（`web/pane-lens.ts`）决定，纯函数、可单测。

  | 窗格数 | 每格 span（6 轨） | 视觉 |
  | ---: | :--- | :--- |
  | 1 | `6` | 单窗格（基线） |
  | 2 | `3,3` | 左右并列 |
  | 3 | `3,3,6` | 上两格 + 下通栏 |
  | 4 | `3,3,3,3` | 四方格 |
  | 5 | `2,2,2,3,3` | 上三 + 下两 |
  | 6 | `2,2,2,2,2,2` | 3×2 全员 |

- 窗格头 **34px**、`--paper-2`、底部 1px `--line`。从左到右：20px 头像（`--tone` 底与字）/
  镜片 `<select>`（无边框，hover 才出边）/ 6px 状态点 / 右侧 `↓ N` / `×`。
- 单窗格 + `room`：`html[data-panes="single-room"]`，窗格头与格线隐藏，`#timeline-actions`
  （对话目录 + 底部浮标）与既有几何保留——**基线视觉零回归**。
- 其余模式：`html[data-panes="grid"]`，隐藏 `#timeline-actions`，改由每格头部的 `↓` 接管；
  `.pane .timeline` 的左右内边距收到 16px（窗格内不再做 1040px 阅读列居中）。
- ≤760px：窗格墙单列纵向滚动（每格最小 300px 高），不产生横向滚动；窄屏一次看一格。

### 13.2 镜片（`room` / `agent:<actorId>`）

| 事件 | `room` | `agent:<id>` |
| :--- | :--- | :--- |
| `message.created`（用户） | 完整气泡 | 折叠为一行 `你 · HH:mm · 首行 60 字` 的 `<details>`；展开是全文 + 回复/复制 |
| `message.created`（本 Agent） | 完整气泡 | 完整气泡 |
| `message.created`（其他 Agent） | 完整气泡 | 不显示 |
| `turn.*` / `turn.*.delta` / `reasoning.*` / `tool.progress*` | 显示 | 仅 `resolveTurnTarget(envelope) === <id>` |
| `supervision.*` / `operator.dispatch` / 记忆活动 / `generic` / `session.*` | 显示（session 只进全局） | 不显示 |

- 目标解析：`body.targetActorId` → `state.turns` 已有目标 → `envelope.to` → `actor`。终态事件没有 target
  时必须靠 `state.turns`，否则失败/中断会从车道消失（D-044 的同一条约束）。
- 车道保留 Turn 卡（含状态、错误、取消）；「失败也要看见」是车道存在的理由。

### 13.3 窗格头与交互

- `select` 换镜片：清空该格 DOM，按回填日志重放，滚到底；持久化。
- `×`：只在 `count > 1` 出现；移除该镜片，后面的前移，统一重绘并持久化。
- `↓ N`：该格离底 >120px 时出现；`N` 是暂停后新增的条目数（`>99` 写 `99+`）；
  点击恢复该格跟随并瞬时贴底。它**不是**未读系统，不写 localStorage/DB。
- 状态点：`working`（当前有该 Agent 的非终态 Turn，`--accent` + 3px wash）/ `ready`（`--ok`）/
  `starting|restarting`（`--warn`）/ `failed`（`--danger`）/ `disabled|missing`（`--faint`）；`room` 无点。
- 对话框（顶栏 `▦`）：布局 1 / 2 / 4 / 6 / 8；每格一个镜片下拉；「按 Agent 铺满」（只取启用且非
  `pending_restart`，最多 8）；「重置为单窗格」；「在新窗口打开当前目录」（浏览器窗口 = 独立 SSE，
  用于跨目录/跨屏幕）。
- 键盘与读屏：`▦`、每格 `select`/`↓`/`×` 都是原生可聚焦元素；每格 `role="group"` 且
  `aria-label="窗格 N：<镜片名>"`；只有主格保留 `aria-live="polite"`，其余 `aria-live="off"`（避免 6 份重复播报）。

### 13.4 状态与回填

- 回填日志：`state.paneLog` 保存最近 **300** 条可见且非 delta 的事件（`{envelope, targetActorId}`），
  新建窗格、切镜片、从 1 格扩到 4/6 格时按序重放。DOM 仍按 `TIMELINE_MAX_ITEMS = 500` / 格裁剪；
  日志超限只影响「新建窗格能看到多早的历史」，不影响任何格的实时增量。
- 持久化：`localStorage["aichatlink:panes"] = {"count":4,"lenses":["room","agent:pi-architect",…]}`。
  解析失败/越界 → 夹到 1..6 并补 `room`；名册就绪后对账：名册里不存在的 `agent:` **回落 `room` 并写回**；
  已停用的 Agent **保留**（仍可看历史输出）。
- `context.reset`：清空所有格子的 DOM/节点表/裁剪/日期分隔/角标 + 清空回填日志；每格按镜片刷新空态。
- 历史回放 `?conv=`：所有格按同一 `conversationView` 回放；车道只显示该 Agent 的历史段；输入器不因活纪元的
  Turn 被锁（既有 gate 不变）。

### 13.5 基线保持（不可回归）

- 默认仍是「单窗格 + 房间」：头隐藏、`#timeline-actions` 可见、`#jump-latest` 位置由 composer dock 几何决定。
- 一个 composer、一份 `state.turns`、一份忙碌锁：6 格同时看也是一次解锁。
- 活动栏点某 Agent：优先跳到**该 Agent 的车道**里的最新可见回复；没有车道才跳主格。
- TOC 只属于单窗格基线；多格隐藏（它是阅读工具，不是监看工具）。

### 13.6 滚动与跟随

- 每格一条 `createLatestFollower` + 一个 `MutationObserver`；滚动、暂停、贴底互不影响。
- **多格下不提供「滚回底部自动恢复跟随」**：程序化跟随产生的延迟 `scroll` 事件会在用户暂停后到达，
  实测会把暂停的格子重新贴底（4 格复现）。暂停后只通过该格 `↓` 或自己发送恢复。
  这是对 §九 的一处修订，原因是一次可复现的竞态，不是偏好。
- 自己发送只恢复**主格**（`panes[0]`）的跟随；其他格保持各自的阅读位置。

### 13.7 禁止

- 不给窗格各自开 EventSource / 各自 bootstrap / 各自 runtime（HTTP/1.1 同源 6 连接 + 进程数）。
- 不给窗格第二个输入器、第二份 Turn 状态、第二份忙碌锁。
- 不把窗格布局写进 URL / DB / `aichatlink.json`；不跨设备同步。
- 不在 `agent` 车道里显示其他 Agent 的消息、监督事件或记忆活动。
- 不用状态色做装饰；不给窗格加「边框 + 阴影 + 圆角」三件套；不新增字号/hex。
- 不让多格把活动栏/输入器挤出视口：≤760px 单列纵向，其余按 6 轨 plan。

### 13.8 验收

1. `npm run typecheck`、`npx vitest run`、`npm run build` 全通过；`/pane-lens.js`、`/pane-view.js` 200。
2. 1/2/4/5/6 格在 1600×1000 与 1280×800：span/rect 符合 §13.1，无横向滚动。
3. 430×900：单列、可纵向滚动、无横向滚动；窗格头不溢出。
4. 4 格 + 3 个 Agent 真实回合：每格只有自己的 Agent 与折叠的用户提示；room 有全部；忙碌锁一次解锁。
5. 暂停一格后其他格继续增长：该格 `scrollTop` 不变、`↓` 出现且角标计数；点击后回到底部。
6. 刷新/切镜片/扩格：布局与回填一致；名册里不存在的 Agent 回落 `room`。
7. `context.reset`：所有格清空且空态按镜片正确；历史回放 4 格不锁输入器。
8. 明/暗两套：窗格头、状态点、折叠提示可辨；`--faint` 不承载信息。

## 十四、显示尺度（大屏适配）

触发证据（2026-11-19，用户换到台式机大屏后）：「对话框、右侧图标明显有点小了」。
核对实现：`--rail-w`/`--sidebar-w`/`--column-max`/头像格子/顶栏图标/按钮高度/文本域自增高上限全是绝对 px，
12 条 `@media`/`@container` 断点里没有一条在 >1600px 时动作，于是 27" 2560×1440 上看到的仍是笔记本毫米尺寸。

### 14.1 一条原语：`--px`（设计像素）

```css
:root { --px: 0.0625rem; }              /* 16px 根字号时正好 1px */
html  { font-size: clamp(1rem, calc(1rem + (100vw - 1600px) / 300), 1.4rem); }
```

- 所有**几何**写 `calc(N * var(--px))`；所有**字号**继续用 `--fs-*`（`rem`）。两者共用同一个乘数，
  所以 19.2px 的根字号必然配 36px 的格子，不会出现「字撑破头像」。
- **基准是 `1rem`，不是裸 `vw`**：系统/浏览器字号设置仍然生效，满足 WCAG 2.2 SC 1.4.4 与 F94
  （只用视口单位定字号会让用户字号设置失效）。视口只贡献增量。
- 斜坡：≤1600px 恒为 1×（笔记本档零变化），1920 ≈ 1.067×，2560 = 1.2×，≥3520 封顶 1.4×。
- **不缩放**：`1px` 发丝线、`--shadow-*`、`@media`/`@container` 断点、`--r-pill`。
  发丝线放大到 1.2px 会发糊；断点必须继续表示「窗口有多宽」，不能变成「UI 有多大」。
- JS 侧同一乘数：`designPx(n)`（`web/app.ts`）用于文本域自增高上限与浮标边距；
  活动栏列数走 CSS 变量 `--rail-cols`，列宽由 `--rail-cell` 决定，**不再由 JS 写死 30px**。

| 档位 | 根字号 | 活动栏格子 | 阅读列上限 | 顶栏高 |
| --- | --- | --- | --- | --- |
| ≤1600px | 16px | 30px | 1040px | 56px |
| 1920 | 17.07px | 32px | 1110px | 59.7px |
| 2560 | 19.2px | 36px | 1248px | 67.2px |
| ≥3520 | 22.4px | 42px | 1456px | 78.4px |

### 14.2 逃生口

用户若仍嫌小，用浏览器缩放（Ctrl/Cmd `+`）或系统「显示大小」——两者都会乘在这条斜坡之上。
**不做常驻「界面大小」开关**：它会把自动适配变成一句「你自己调」的借口，并与 §七「不设无决策常驻控件」冲突。

### 14.3 验收

1. `npm run typecheck`、`npx vitest run` 全通过，`npm run build` 通过。
2. 1280×800 / 1600×1000 / 430×900 三档与改动前**逐像素一致**（同一份 `dist/web`、同一组视口、PNG md5 相同）。
3. 1920 / 2560 两档：根字号、格子、阅读列按 §14.1 表增长；`scrollWidth == clientWidth`（无横向滚动）。
4. `/setup` 共用同一 token：顶栏、名册轨道、对话框随尺度变化，无横向滚动。
5. 明/暗两套：几何变化不改颜色，正文对比度仍 ≥4.5:1。
